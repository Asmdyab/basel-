# K-HUB Frontend UI

واجهة React لنظام K-HUB لحجز الملاعب، مراجعة الدفع، تسجيل التمارين، وإدارة صفحات المستخدمين الخاصة.

## التشغيل

1. انسخ ملف البيئة:

```bash
cp .env.example .env
```

2. تأكد أن رابط الـ API صحيح داخل `.env`:

```env
VITE_API_BASE_URL=https://localhost:7187
```

3. ثبّت الحزم وشغّل المشروع:

```bash
npm install
npm run dev
```

الرابط المحلي المعتاد:

```text
http://localhost:5173
```

## الصفحات

- `/` الصفحة الرئيسية
- `/courts` الملاعب
- `/courts/:courtId` تفاصيل الملعب
- `/book/:courtId` إنشاء حجز
- `/my-bookings` حجوزات المستخدم
- `/training` اختيار اللعبة وعرض التفاصيل والمواعيد والمدربين
- `/training/:sportId` تفاصيل برنامج التدريب واختيار الموعد والكابتن
- `/training/coaches/:coachId` ملف الكابتن والبطولات والشهادات
- `/training/register/:sportId` استكمال نموذج التسجيل ورفع إثبات الدفع
- `/profile` الصفحة الخاصة بالمستخدم الحالي
- `/admin` لوحة الإدارة
- `/admin/users` قائمة ملفات المستخدمين الخاصة
- `/admin/users/:userId` ملف مستخدم محدد للإدارة
- `/schedule` جدول الحجوزات

## الصفحة الشخصية الخاصة

الصفحة تعرض لصاحب الحساب:

- الصورة الشخصية.
- الاسم والإيميل والموبايل والسن واللعبة المفضلة.
- عدد الحجوزات وإحصائيات الحالات.
- معلومات الحجوزات وصور إثبات الدفع.
- طلبات التسجيل في التمرين وصور المستخدم وإثبات الدفع.
- رصيد النقاط وسجل إضافتها أو خصمها.

الإدارة تستطيع فتح ملفات المستخدمين من `/admin/users` وإضافة أو خصم النقاط ومراجعة طلبات التمرين.

## الحماية الحالية

- `/profile` محمية بـ `ProtectedRoute` وتعرض حساب المستخدم الحالي فقط.
- مسارات `/admin/users` محمية بـ `AdminRoute` ولا تفتح إلا لدور `Admin`.
- التوكن محفوظ باسم `accessToken` ويُرسل إلى الـ ASP.NET Core API.

> ملاحظة: البيانات الجديدة الخاصة بالصفحات والنقاط وطلبات التمرين مخزنة حاليًا في `localStorage` كنموذج Frontend. الحماية الحقيقية ومشاركة البيانات بين أجهزة المستخدم والإدارة تتطلب Endpoints وصلاحيات وقاعدة بيانات في الـ Backend.
